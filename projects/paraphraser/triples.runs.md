## How to run the chunks (READ FIRST)

**Do NOT launch all chunks in parallel.** Each chunk is ~80–100 subagents × ~430 tok/triple × ~2,900 triples ≈ **1.3M+ subagent tokens per chunk**. Firing the whole `data/runs/batched/` set at once would burn **>10M tokens in minutes**, blow through rate limits, and give no chance to inspect output between runs.

Run procedure:

1. **One chunk at a time, sequentially.** Invoke a single chunk, wait for it to finish, then persist and inspect before starting the next:
   ```
   Workflow({ scriptPath: "<abs>/projects/paraphraser/data/runs/batched/chunk_NNN.workflow.js" })
   ```
2. **At most 1–2 chunks in flight**, never the full set. If you parallelize at all, cap it at 2 and watch the token meter.
3. **Persist after each chunk** — append the returned `triples` to `data/triples.claude-code.jsonl` (snippet in the workflow header). The result is in-memory only until you write it.
4. **Check `failed` / `mismapped`** in the return value before moving on. Re-run a chunk only if `failed` is non-trivial.
5. **Append a row to this log** for the run_id you just completed.
6. **Re-emit, don't hand-edit**, when remaining work changes: `python3 emit_chunks_batched.py` with the live `--done-file` repacks only outstanding jobs (and would fix the current overlap + tier skew).

The subagent-concurrency cap inside a single Workflow already limits fan-out *within* one chunk; the rule above is about not stacking *chunks* on top of each other.

### ⚠️ Data-integrity finding (2026-06-23, surfaced by chunk_011): `source_id` is NOT unique

`data/run_manifest.jsonl` has **10,000 jobs but only 1,650 distinct `source_id`s; 814 ids collide**, each mapping to up to **20** different seed sentences — across every domain (consumer 245, arxiv 215, dialogue 134, wiki 132, news 88). **Root cause:** `build_seeds.py` assigns `source_id` at the **document** level (`amazon:50` = review #50, `arxiv:<paper>` = one abstract, `dd:<dialog>:<turn>`) but emits **multiple sentences per document**, so distinct seeds share an id.

**Impact is limited and does NOT block training:**
- The `(source, instruction, target)` triples are **valid** — the model rewrote the real seed text fed to it; only the `source_id` *tag* is non-unique. Verified on chunk_011: all 105 "mismapped" rows are benign (real seeds + detok artifacts), 0 cross-contamination.
- Training never reads `source_id`. The filter dedups on `(source, instruction)` **text**, not id, so dedup is unaffected.
- **Broken:** anything keyed on `source_id` — per-source coverage stats, and the `mismapped` detector's manifest cross-checks (it over-counts on collisions, as in chunk_011's 105).

**FIXED 2026-06-23 (generator + backfill written):**
- `build_seeds.py` now emits `source_id = "<doc-id>#<sentence-index>"` (e.g. `amazon:50#2`, `dd:1268:58#0`) — unique per sentence. Verified on a synthetic 3-sentence doc.
- `backfill_source_ids.py` re-keys data already generated under the old scheme: builds the canonical map from `seeds.jsonl` (distinct source texts per old id, first-appearance = document order), applies it to `seeds.jsonl`, `run_manifest.jsonl`, and `triples.claude-code.jsonl` (triples matched on an alphanumeric source signature, with an `(old-id, instruction)→manifest` fallback for echo-drifted sources). Triple text is untouched — only the `source_id` tag changes. Backs up each file (`.bak-preBackfill`); rows already containing `#` are skipped.
- **Dry-run on the live corpus:** manifest collisions **814 → 0**; triples re-keyed 32,962 direct + 130 fallback, 60 pre-schema pilot rows have no id, 6 unmatched echoes keep their old id; 30 residual "collisions" are cosmetic echo-drift (e.g. `María José`/`Maria Jose`), not id errors.

**⚠️ Run the backfill ONCE, AFTER the chunk queue (012–014) finishes.** It reads `seeds.jsonl` (old ids) to build the map and rewrites it, so it is not safely re-runnable once `seeds.jsonl` is re-keyed; the remaining chunks emit old-style ids that the final single pass folds in.
